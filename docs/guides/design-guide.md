# 디자인 가이드

> 상태: v0.2 · 2026-11-21
> "어떤 원칙으로, 어떤 UI 패턴을 쓰는가"를 다룹니다. 값은 [style-guide](style-guide.md), 뼈대는 [layout-guide](layout-guide.md), 부품은 [component-guide](component-guide.md)를 따릅니다.
> 관련 결정: [0003 생성은 드로어](../decisions/0003-create-with-drawer.md), [0004 폴더는 목록에서만](../decisions/0004-folder-only-in-list.md)

## 1. 디자인 원칙

1. **열린 느낌.** 상자 안에 정보를 꽉 채우지 않는다. 여백으로 구분하고, 테두리와 배경은 꼭 필요할 때만 쓴다.
2. **바로 남긴다.** 무언가를 만드는 데 필요한 입력은 최소로. 나머지는 나중에 채운다.
3. **할 일이 먼저.** 통계보다 "지금 무엇을 하면 되는지"를 먼저 보여준다.
4. **같은 일은 같은 모양.** 추가는 어디서나 같은 드로어, 확인은 어디서나 같은 모달.
5. **자동으로 할 수 있으면 묻지 않는다.** 상태, 진행률처럼 계산할 수 있는 값은 사용자가 고르지 않는다.
6. **두 가지 테마에서 똑같이 읽힌다.** 라이트·다크 모드를 모두 지원한다. 새 화면은 두 모드에서 확인한다. ([0002](../decisions/0002-light-and-dark-mode.md))

### 1-1. 시각 표현 규칙

- **아이콘:** `AppIcon`으로 넣는 선 아이콘만 쓴다. 이모지를 아이콘 대신 쓰지 않는다. (지금 목표 드로어의 🎨 등 6곳)
- **그라데이션:** 주 버튼(`PrimaryButton`)에만 쓴다. 카드, 배경, 메뉴에는 쓰지 않는다.
- **테두리 vs 그림자:** 같은 높이의 면은 테두리로, 떠 있는 면(메뉴, 모달, 드로어)만 그림자로 구분한다.
- **색으로만 구분하지 않는다:** 상태·선택은 아이콘, 글자, 굵기를 함께 쓴다.

## 2. 폴더 컨셉

- 폴더 모양은 **프로젝트 목록 카드에서만** 쓴다. 목록에서 "내 프로젝트 묶음"이라는 정체성을 보여주는 장치다.
- 디테일 페이지, 설정, 드로어에는 폴더 모양을 쓰지 않는다. 일반 페이지 규칙을 따른다.
- 디테일 페이지에서 프로젝트를 구분할 때는 프로젝트 색을 **이름 앞의 점이나 아이콘**에만 쓴다.

## 3. UI 역할 규칙

한 화면 요소에 역할을 섞지 않는다.

| 하는 일 | UI | 닫힌 뒤 |
|---|---|---|
| 만들기 (프로젝트·목표·메모) | **오른쪽 드로어** | 저장 후 목록 유지, 프로젝트는 디테일로 이동 |
| 상세 보기·빠른 수정 (목표) | 오른쪽 드로어 | 바로 반영 |
| 많은 항목 수정 (프로젝트) | 별도 수정 페이지 | 저장 후 디테일로 이동 |
| 선택 (프로젝트 고르기) | 선택 모달. 좁은 화면의 프로젝트 전환만 드로어 | 고른 값만 돌려줌 |
| 작은 설정 (메인 프로젝트 지정 등) | 설정 모달 | 저장 |
| 삭제·상태 변경 확인 | 확인 모달 (`AlertModal`) | 실행 또는 취소 |
| 목록 좁히기 (상태 필터) | 목록 위에 항상 보이는 칩 | 목록만 좁힘 |
| 정렬 | 목록 툴바 | 목록만 정렬 |
| 앱 전체 설정 | 설정 페이지 (`/settings`) | 즉시 저장 |

- 이름·기간·설명 같은 내용 수정은 설정 모달에 넣지 않는다.
- 긴 글(프로젝트 설명 등)은 입력칸 옆 "자세히 쓰기"로 드로어를 열어 쓸 수 있다. "적용"을 눌러야 원래 폼에 반영되고, 저장은 원래 화면에서 한다.
- 태스크 추가·수정은 현재 모달이며, v1.x에서 드로어로 바꾼다.

## 4. 생성 드로어 패턴

모든 생성 드로어는 같은 구조를 쓴다.

```
[닫기]                                  [전체 화면]
(아이콘 블록 48×48)
제목 입력 (큰 글씨, placeholder "새 ○○")
안내 한 줄 (선택)
───────────────
라벨 | 값            ← 라벨 행 반복
라벨 | 값   자동 계산 ⓘ
───────────────
▸ 추가 설정   요약   나중에 해도 돼요   ← 접힘
───────────────
단축키 안내            [취소] [○○ 추가]
```

- 필수 입력은 **이름 하나**. 이름이 비어 있으면 추가 버튼이 비활성화된다.
- 자동 계산 값(상태 등)은 행에 보여주되 고르지 않게 한다. 오른쪽에 "자동 계산"과 규칙 설명 툴팁을 둔다.
- 나중에 정해도 되는 항목(목표 태그, 메인 설정)은 "추가 설정"에 접는다. 접힌 줄에 요약(예: "목표 태그 기본 4개")을 보여준다.
- 설정에서 꺼진 기능의 행은 그리지 않는다.
- `⌘ Enter`(Windows `Ctrl Enter`)로 추가, `Esc`로 닫기.
- 닫을 때 입력 중인 내용이 있으면 확인 모달을 띄운다.

## 5. 탭 패턴

- 한 화면에 탭 줄은 **하나만** 둔다. 탭 안에 또 탭을 두지 않는다.
- 페이지 이동이 되는 탭은 주소(URL)와 연결한다. 새로고침해도 같은 탭이 보여야 한다.
- 목록 화면 탭 줄: `[전체] [메인] [즐겨찾기] [맞춤 탭…] [+]`
  - 맞춤 탭이 넘치면 `···` 더보기 메뉴로 접는다.
  - 맞춤 탭은 우클릭 또는 `···`로 이름 변경, 프로젝트 편집, 삭제.
- 탭 디자인은 한 종류(라인 탭)로 통일한다. 폴더 탭 모양은 쓰지 않는다.

## 6. 프로젝트 디테일 페이지

```
브레드크럼                                   [☆] [수정] [···]
● 프로젝트 이름
  설명 한 줄 … 더보기
  기간·D-day · 상태(자동) · #태그
[개요] [목표 n] [태스크 n] [메모] [기록]
──────────────────────────────────────
개요: 왼쪽(넓게) 다음에 할 일 · 목표 / 오른쪽(좁게) 진행률 · 다가오는 일정 · 최근 기록
```

- 페이지 전체가 스크롤된다. 영역별 따로 스크롤을 만들지 않는다.
- 목표·태스크 탭은 전용 화면(보드·캘린더)을 그대로 쓴다. 디테일 안에 따로 목록을 만들지 않는다.
- 팀 탭은 v1에 없다. (PRD 5-4, v2에서 다시 설계)
- 기록 탭은 v1에 넣는다: 프로젝트 타임라인 + 마감일 변경 이력(이전·새 마감일, 사유, 시각).
- 활동 잔디와 소개 섹션은 v1.x에 추가한다.
- 공개해도 되는 섹션(진행률, 목표, 활동 기록, 소개)과 나만 보는 섹션(다음에 할 일, 메모)을 구분해 둔다. v2 공개 페이지에서 앞의 것만 모은다.

## 7. 상태 표현

| 대상 | 상태 | 표시 |
|---|---|---|
| 프로젝트 | 계획 · 진행 중 · 보류 · 완료 | 아이콘 + 글자 |
| 프로젝트 | 지연 | 빨간 경고 아이콘 + "n일 지연" (상태와 별도 표시) |
| 목표 | 미시작 · 진행 중 · 완료 | 아이콘 + 글자 |
| 태스크 | 할 일 · 진행 중 · 완료 | 아이콘 + 글자 |

- 색만으로 상태를 구분하지 않는다. 아이콘이나 글자를 함께 쓴다.
- 상태 색은 `style-guide.md`의 상태 토큰만 쓴다.

### 7-1. 화면 상태 패턴

모든 데이터 화면은 아래 네 상태를 갖는다. 화면마다 직접 문구를 쓰지 않고 공통 컴포넌트를 쓴다.

| 상태 | 보여줄 것 | 컴포넌트 |
|---|---|---|
| 로딩 | 실제 모양과 비슷한 회색 뼈대 (skeleton). 0.3초 안에 끝나면 보여주지 않는다 | `Skeleton` ★ |
| 비어 있음 | 아이콘 + 한 줄 설명 + 만들기 버튼 | `EmptyState` ★ |
| 검색·필터 결과 없음 | "조건에 맞는 ○○가 없어요" + 필터 초기화 버튼 | `EmptyState` (variant) |
| 오류 | 무엇이 안 됐는지 + 다시 시도 버튼 | `ErrorState` ★ |

### 7-2. 알림 패턴

| 상황 | UI | 예 |
|---|---|---|
| 방금 한 일의 결과 + 되돌리기 | 토스트 (아래 가운데, 4초) | "즐겨찾기에서 뺐어요 · 되돌리기" |
| 계속 알아야 하는 제한 | 화면 안 안내 띠 | "보류 중인 프로젝트에는 추가할 수 없어요" |
| 입력 오류 | 입력칸 바로 아래 빨간 글 | "이름을 입력해 주세요" |
| 되돌릴 수 없는 행동 | 확인 모달 (`AlertModal`) | 삭제 |

- 토스트는 `Toast` ★ 하나로 통일한다. 지금 `DeadlineToast`, `FavoriteRemovedToast`가 따로 있다.
- 토스트는 한 번에 하나만 보인다. 새 토스트가 오면 이전 것을 바꾼다.

### 7-3. 폼과 검증

- 검증은 입력칸을 벗어날 때(blur)와 제출할 때 한다. 타이핑할 때마다 빨간 글을 띄우지 않는다.
- 필수 표시는 `*` 대신 필수가 아닌 칸에 "(선택)"을 붙인다. 필수가 이름 하나뿐이라 이 방식이 더 깔끔하다.
- 오류 문구는 zod 스키마 한 곳에서 관리한다. 형식: "○○을(를) 입력해 주세요", "○○은(는) n자까지 쓸 수 있어요".
- 글자 수 제한이 있는 칸은 `현재/최대`를 오른쪽 위에 보여준다.

### 7-4. 용어

화면에 보이는 말은 아래로 통일한다. 코드의 변수 이름은 영어(오른쪽 열)를 쓴다.

| 화면 | 코드 | 쓰지 않는 말 |
|---|---|---|
| 프로젝트 | project | |
| 목표 | goal | |
| 태스크 | task | 업무, 할 일(상태 이름 "할 일"은 예외) |
| 메모 | memo | |
| 메모 화면 주소 | `/memos` | 백로그 (지금 주소 `/backlog`) |
| 메인 프로젝트 | main project | 대표 프로젝트 |
| 즐겨찾기 | favorite | |
| 맞춤 탭 | custom tab | 커스텀 뷰 |

- 목업 데이터(`src/lib/mock/`)의 예시 문장은 데이터 값이라 이 규칙을 적용하지 않는다.

## 8. 문구 톤

- 존댓말, 짧게, 쉬운 말. 예: "이름만 있으면 바로 만들 수 있어요."
- 버튼은 동사로 끝낸다: "프로젝트 추가", "저장", "삭제".
- 빈 화면은 다음 행동을 알려준다: "아직 목표가 없어요. 첫 목표를 추가해 보세요."
- 오류는 무엇을 하면 되는지 말한다: "마감일은 시작일 이후로 골라 주세요."

## 9. 접근성

- 클릭되는 것은 `<button>` 또는 `<a>`. `div`에 `onClick`을 달지 않는다. (지금 `ProjectBoardCard`, `ProjectListRow` 2곳)
- 카드 전체를 누르는 경우: 제목을 `<a>`로 만들고, 가상 요소(`after:absolute after:inset-0`)로 클릭 영역을 카드 전체로 넓힌다. 카드 안 다른 버튼은 `relative z-10`.
- 키보드 포커스는 `--color-primary-ring` 2px 링으로 항상 보이게 한다. `outline: none`만 쓰고 대체 표시를 안 두는 것 금지.
- 아이콘만 있는 버튼에는 `aria-label`.
- 모달·드로어는 열리면 포커스를 안으로, 닫히면 연 버튼으로 돌려준다.
- 글자와 배경 대비 4.5:1 이상 (큰 글씨 3:1).
- 터치 영역은 최소 40×40px.
