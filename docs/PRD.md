# PRD — 프로젝트 기록 앱 (가칭: Tessera / 잇다)

> 상태: v0.2 · 2026-11-21
> "무엇을, 왜 만드는가"만 다룹니다. 화면 규칙은 [design-guide](guides/design-guide.md), 작업 순서는 [roadmap](roadmap.md)을 봅니다.
> 지금 코드가 이 문서와 다른 점은 [tech-debt](tech-debt.md)의 "P" 항목에 모아 둡니다.

## 0. 용어

| 용어 | 뜻 |
|---|---|
| 프로젝트 | 기간과 목적이 있는 일의 묶음. 목표와 태스크를 담는다 |
| 목표 | 프로젝트 안에서 이루고 싶은 결과. 여러 태스크로 이뤄진다 |
| 태스크 | 실제로 할 일 하나. 보드에서 할 일 → 진행 중 → 완료로 움직인다 |
| 메모 | 떠오른 생각을 빠르게 적은 것. 나중에 목표나 태스크로 등록할 수 있다 |
| (백로그) | 별도 기능이 아니다. 메모 화면의 예전 주소 `/backlog`는 `/memos`로 리다이렉트된다. 디테일 하위 주소는 tech-debt D-3 |
| 메인 프로젝트 | 가장 자주 보는 프로젝트 하나. 사이드바 위에 고정된다 |
| 맞춤 탭 | 사용자가 이름을 붙이고 프로젝트를 골라 담은 탭 |
| 목표 태그 | 프로젝트 안에서 목표를 분류하는 이름표 |

## 1. 한 줄 소개

할 일 하나하나를 조각처럼 남기고, 이어서 나만의 프로젝트와 기록을 만드는 **평생 쓰는 개인 프로젝트 기록 앱**.

## 2. 왜 만드나

- 혼자 프로젝트를 하면 계획, 진행, 기록이 흩어지고 끝까지 이어가기 어렵다.
- 할 일 앱은 "오늘 할 일"만 남고, 내가 무엇을 해왔는지는 남지 않는다.
- 나중에는 같이 할 사람을 찾기도 어렵다. 글로 모집하면 실제로 하고 있는지 알 수 없다.

## 3. 핵심 가치

| 가치 | 의미 | 제품에서의 모습 |
|---|---|---|
| 자유롭게 | 프로젝트, 목표, 태스크를 각각 따로 만들어도 된다 | 무엇이든 단독으로 생성 가능 |
| 쉽게 | 생각나면 바로 남긴다 | 생성은 드로어, **이름만 필수** |
| 연결 | 필요할 때 이어 붙인다 | 태스크 → 목표 → 프로젝트 연결, 메모 → 목표/태스크 등록 |
| 기록 | 해온 것이 쌓여 나를 보여준다 | 활동 잔디, 기록 탭, 완료 후 회고 |

## 4. 사용자

- **지금:** 사이드 프로젝트를 혼자 하는 개발자·디자이너 (만드는 사람 본인 포함)
- **나중:** 함께할 팀원을 찾는 사람, 공개된 프로젝트를 구경하고 참여하고 싶은 사람

## 5. 범위

### 5-1. 지금 만들 것 (v1)

| 영역 | 기능 |
|---|---|
| 프로젝트 | 목록(폴더 카드), 추가 드로어, 디테일 페이지(개요·목표·태스크·메모·**기록** 탭), 수정 페이지, 즐겨찾기, 메인 프로젝트 |
| 목표 | 목록, 추가/상세 드로어, 프로젝트 연결, 목표 태그(최대 2개), 상태 자동 계산 |
| 태스크 | 보드(드래그), 캘린더, 추가/수정, 목표 연결 |
| 메모 | 빠른 기록, 이전 메모, 목표·태스크로 등록 |
| 탭 | 기본 탭(전체·메인·즐겨찾기) + **맞춤 탭** |
| 설정 | 기능 켜기·끄기, 새 프로젝트 기본값, 보기 설정, 내보내기 |
| 검색 | 통합 검색 모달 |

### 5-2. 다음 (v1.x)

- 디테일 페이지: 활동 잔디, 소개
- 태스크 추가·수정도 드로어로 통일
- 실제 데이터 저장소 연결 (목업 → API/DB)

### 5-3. 나중 (v2)

- 완료 후 회고 → 이력서 내보내기
- 프로젝트 공개 페이지
- 팀원 모집, 참여 요청, 멤버 관리

### 5-4. 하지 않는 것 (v1)

> **v1은 혼자 쓰는 개인용이다.** 팀과 관련된 화면(팀 메뉴, 팀 탭, 팀 선택, 멤버)은 v1에서 모두 숨긴다. 데이터의 `teamId` 필드와 코드는 지우지 않고 v2에서 다시 설계한다.

- 스프린트 관리 (현재 빈 페이지, 제거)
- 팀 메뉴, 팀 관리 모달, 회사용 권한 안내 → v1에서는 메뉴에서 숨긴다. 코드는 지우지 않고 v2에서 개인 사용 기준으로 다시 설계한다.
- 리포트 메뉴 → 숨긴다. "이번 주 진행률"과 디테일 페이지 개요가 역할을 대신한다.
- 플레이그라운드 → 개발 환경에서만 보인다.

### 5-5. 품질 기준 (비기능)

| 항목 | 기준 |
|---|---|
| 반응형 | 375px(모바일)부터 1440px 이상까지 모든 화면 사용 가능 |
| 테마 | 라이트·다크 모두 지원, 대비 4.5:1 이상 |
| 접근성 | 키보드만으로 모든 기능 사용 가능, 스크린 리더 이름 제공 |
| 성능 | 목록 화면 첫 표시 1초 안 (데이터 100개 기준) |
| 데이터 | 전체 내보내기(JSON)로 언제든 백업 가능 |

## 6. 데이터 관계

```
프로젝트 1 ── N 목표 1 ── N 태스크
    │                       │
    └──────── N 태스크 ──────┘   (목표 없이 프로젝트에 바로 연결 가능)

메모 ── (등록) ──> 목표 또는 태스크 하나
맞춤 탭 ── N 프로젝트 (직접 고른 묶음)
설정 1개 (사용자당)
```

- 목표와 태스크는 프로젝트 없이도 만들 수 있다.
- 진행률은 **저장하지 않고 계산한다.** 프로젝트는 소속 태스크, 목표는 연결된 태스크 기준.
- 상태는 날짜와 하위 항목으로 **자동 계산한다.** (규칙은 7장)

## 7. 핵심 규칙

### 7-1. 생성

| 항목 | 필수 | 나머지 |
|---|---|---|
| 프로젝트 | 이름 | 색상, 설명, 기간(마감 없음 허용), 목표 태그, 메인 여부 |
| 목표 | 이름 | 설명, 프로젝트, 목표 태그, 기간 |
| 태스크 | 이름 | 설명, 목표, 우선순위, 마감일 |

### 7-2. 프로젝트 상태 (자동)

| 상태 | 조건 |
|---|---|
| 계획 | 시작일이 오늘 이후 |
| 진행 중 | 시작일이 오늘이거나 지남 |
| 지연 | 진행 중이면서 마감일이 지남 (상태가 아니라 표시) |
| 보류 | 사용자가 직접 설정 |
| 완료 | 사용자가 직접 설정 |

- 보류·완료 프로젝트에는 목표·태스크를 추가할 수 없다.
- 보류·완료 상태에서는 마감일을 바꿀 수 없다.
- 마감일을 바꾸면 이력(이전 값, 새 값, 사유, 시각)을 남긴다.

### 7-3. 목표 태그

- 프로젝트마다 최대 10개. 목표는 그중 최대 2개를 고른다.
- 새 프로젝트를 만들 때 **설정의 기본 태그를 복사**해 넣는다.
- 설정의 기본 태그를 바꿔도 이미 만든 프로젝트의 태그는 바뀌지 않는다.

### 7-4. 맞춤 탭

- 기본 탭: 전체, 메인, 즐겨찾기 (삭제 불가)
- 맞춤 탭: 이름을 정하고 프로젝트를 **직접 골라** 담는다. 최대 5개.
- 탭 줄 끝의 `+`로 만들고, 이름 변경·프로젝트 넣고 빼기·삭제·순서 변경이 가능하다.
- 프로젝트, 목표, 메모 화면에서 같은 탭을 공통으로 쓴다.
- 즐겨찾기는 데이터 구조상 맞춤 탭의 한 종류로 저장한다.
- 조건으로 자동 모으기는 v2에서 검토한다.

### 7-5. 전체 설정

| 분류 | 항목 | 기본값 |
|---|---|---|
| 기능 사용 | 메인 프로젝트 | 켜짐 |
| | 목표 | 켜짐 |
| | 프로젝트 색상 | 켜짐 |
| 새 프로젝트 기본값 | 기본 목표 태그 (최대 10개) | 기획, 개발, 디자인, 데이터 |
| | 기본 색상 | 없음(회색) |
| 보기 | 테마 | 시스템 설정 따르기 (라이트 / 다크 / 시스템) |
| | 태스크 기본 화면 | 보드 |
| | 한 주의 시작 | 월요일 |
| 데이터 | 전체 내보내기 | - |

- 기능을 끄면 **화면에서만 숨긴다.** 데이터는 지우지 않는다.
- 꺼진 기능과 관련된 입력 줄은 드로어와 화면에서 사라진다.

## 8. 성공 기준 (v1)

- 프로젝트를 만드는 데 10초 안에 끝난다 (이름 입력 → 추가).
- 디테일 페이지에 들어오면 "다음에 할 일"이 첫 화면에 보인다.
- 모든 생성 화면이 같은 드로어 구조를 쓴다.
- 새 화면을 만들 때 스타일 가이드 밖의 값(하드코딩 색·간격)을 쓰지 않는다.
- 라이트·다크 모드 어느 쪽에서도 글자가 안 보이는 화면이 없다.
