# docs

이 프로젝트의 기획, 규칙, 작업 계획을 모아 둔 폴더입니다. AI 도구도 작업 전에 이 문서들을 읽습니다. (`CLAUDE.md` 참고)

## 구조

```
docs/
  README.md            ← 지금 이 문서 (목차)
  PRD.md               ← 무엇을, 왜 만드나
  roadmap.md           ← 단계별 작업 계획과 진행 상황
  tech-debt.md         ← 정리 안 된 것, 고쳐야 할 것 목록
  guides/
    design-guide.md    ← 디자인 원칙과 UI 패턴
    style-guide.md     ← 색, 글자, 간격 같은 값 (토큰)
    layout-guide.md    ← 화면 뼈대, 반응형
    component-guide.md ← 컴포넌트 목록과 사용법
    code-guide.md      ← 코드 작성 규칙 (JSDoc, 이름, 폴더, 확인)
    git-guide.md       ← 브랜치, 커밋, push, PR 규칙
  decisions/           ← "왜 이렇게 정했나" 기록 (ADR)
    0001-even-font-sizes.md
    ...
```

## 문서 순서와 우선순위

> 문서 우선순위는 **이 표 한 곳에서만** 정한다. 다른 문서(CLAUDE.md 포함)는 이 표를 가리키기만 한다.

| 순위 | 문서 | 답하는 질문 | 종류 |
|---|---|---|---|
| 1 | `PRD.md` | 무엇을, 왜 만드나? | 규칙 |
| 2 | `guides/design-guide.md` | 화면을 어떤 패턴으로 만드나? | 규칙 |
| 3 | `guides/style-guide.md` | 색·글자·간격 값은? | 규칙 |
| 4 | `guides/layout-guide.md` | 페이지 뼈대, 반응형은? | 규칙 |
| 5 | `guides/component-guide.md` | 어떤 컴포넌트를 쓰나? | 규칙 |
| 6 | `guides/code-guide.md` | 코드는 어떻게 쓰나? | 규칙 |
| 7 | `guides/git-guide.md` | 커밋·브랜치·PR은 어떻게 하나? | 규칙 |
| - | `roadmap.md` | 지금 무슨 작업을 할 차례인가? | 계획 |
| - | `tech-debt.md` | 고쳐야 할 게 뭐가 남았나? | 현황 |
| - | `decisions/` | 왜 이렇게 정했나? | 기록 |

- **규칙 문서끼리 충돌하면 순위가 높은(숫자가 작은) 문서를 따른다.**
- 충돌을 발견해도 **작업을 멈추고 하나씩 묻지 않는다.** 순위대로 판단해 작업을 계속하고, 작업 단위가 끝날 때 발견한 충돌과 고칠 안을 **한 번에 모아서** 알린다.
- **계획·현황·기록 문서는 규칙을 바꾸지 못한다.** roadmap은 순서만, tech-debt는 남은 일만, decisions는 이유만 담는다.
- 결정(`decisions/`)을 새로 하면 같은 PR에서 해당 규칙 문서도 고친다. 규칙 문서에 반영되지 않은 결정은 아직 적용되지 않은 것으로 본다.

## 문서와 코드가 다를 때

문서에는 아직 만들지 않은 목표 상태(★ 토큰, `CreateDrawer` 등)가 적혀 있다. 그래서:

- 문서를 **목표**로 본다. 지금 코드가 다르다고 해서 버그로 보지 않는다.
- **지금 작업 범위 안이면** 문서에 맞춰 고친다.
- **범위 밖이면 고치지 않는다.** `tech-debt.md`에 이미 있는지 확인하고, 없으면 추가한 뒤 사용자에게 알린다.

## 문서 관리 규칙

- 한 규칙은 **한 문서에만** 쓴다. 다른 문서에서는 링크로 가리킨다.
- 큰 결정을 바꾸면 `decisions/`에 새 파일을 추가한다. 예전 결정 파일은 지우지 않고 "대체됨"으로 표시한다.
- 작업을 끝내면 `roadmap.md`의 체크박스와 `tech-debt.md`의 해당 항목을 같은 PR에서 갱신한다.
